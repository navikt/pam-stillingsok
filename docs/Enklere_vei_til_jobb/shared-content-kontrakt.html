Det teamene må avtale

Punktene under kan brukes som møteagenda. Åpne feltene for forslag til kontrakt og en liten JSON:API-payload.

Møteagenda
  1. Eksakte Drupal bundle- og feltnavn.
  2. Stabile nøkler eller garanti for stabile UUID-er.
  3. Om any-matching dekker UX-skissene.
  4. Om frontend eller API-et utfører matchingen.
  5. Hvordan media og include-stier skal se ut.
  6. Hvilke tekstfelt som er ren tekst eller HTML.
  7. Rot-UUID-er og eksempelpayload for alle tre frontendoperasjonene.
Minste komplette stagingdatasett
  • Tre spørsmål med enkeltvalg og flervalg.
  • Ett standardresultat uten matching.
  • Ett resultat koblet til ett svaralternativ.
  • Ett FAQ-spørsmål med rikt svarinnhold.
  • Én quizseksjon med minst to spørsmål.
  • UUID-er og ferdige include-stier.
Valideringsregler
  • Nøkler er unike, stabile og maksimalt 128 tegn.
  • Relasjonsrekkefølge bevares.
  • Alle refererte ressurser finnes i included.
  • Quizspørsmål har minst to alternativer og nøyaktig ett riktig svar.
  • Lenker er relative eller bruker HTTPS.
  • HTML bruker avtalt format og saniteres også i frontend.
  • Manglende obligatoriske felt gir en tydelig kontraktfeil.
Eksempel på ResultItem i JSON:API

Feltnavnene er forslag. Mellomleddet holder matchingreglene utenfor den delte artikkelen. 

{
  "type": "paragraph--result_item",
  "id": "5d18d998-3a95-4c37-bc10-8fde749488b8",
  "attributes": {
    "field_show_by_default": false
  },
  "relationships": {
    "field_content": {
      "data": {
        "type": "node--shared_content",
        "id": "article-uuid"
      }
    },
    "field_match_options": {
      "data": [
        {
          "type": "paragraph--onboarding_option",
          "id": "option-uuid"
        }
      ]
    }
  }
}

Statisk arbeidsdokument. Ingen data sendes eller lagres. Åpnes direkte i nettleseren uten bygging eller eksterne avhengigheter.
